# Agentic design systems: definitions, history, and disagreements

Scope note: definitions, public history, and disagreements only, as of November 2026. No build roadmap. Every claim below is tied to a page opened or a search snippet in this research pass. Where a page was not opened in full, that is stated. Nothing here is a coining claim unless a source says so. This pass did not establish a single first use of the exact phrase "agentic design system."

Related phrases that show up beside it, and are not interchangeable: DS+AI, AI-ready design system, LLM context design, machine-readable design system, agent-ready design system, AI-native design system, design context, agentic UX / AiUX, agents as users, self-healing design system, agentic hub.

## What distinct meanings are in use between 2024 and November 2026?

### Takeaway

By November 2026 the exact phrase is used for at least three different artifacts, and several sources mix them in one sentence. Meaning A is a human design system made readable and checkable by coding or design agents (tokens, component contracts, MCP, Code Connect, registries). Meaning B is a pattern library for the UX of agentic products (plans, tools, handoff, confidence, oversight). Meaning C is a design system that agents themselves write or maintain (docs, tokens, themes, pull requests), usually still under a human permission gate. A fourth, explicit taxonomy treats "agentic" as a property of the system (it plans, chooses, builds, and evaluates), stacked on top of traditional, computational, and generative systems. Adjacent talk about "agents as users" of ordinary product UI is easy to collapse into these meanings and should be kept separate.

### Cited Findings

#### Meaning A — a design system agents can read, apply, and be checked against

- Aestheria, in a post that dates its own field snapshot to August 2026, FAQ: "An agentic design system is a design system an AI agent can read, apply, and be verified against when it builds product UI. It encodes tokens, constraints, component contracts, and usage rules as machine-readable context rather than as documentation prose. The distinguishing feature is not that an agent can generate from it, but that the system can determine whether the generated output is correct." The same FAQ says MCP is "one delivery mechanism, not a requirement." — [What is an agentic design system? | Aestheria](https://aestheria.design/blog/what-is-an-agentic-design-system)
- Into Design Systems, summarizing the AI Design Systems Conference 2026 (calendar dates of the conference not on the page): "An agentic design system is infrastructure that lets AI agents autonomously read, reason over and build with your components, tokens and guidelines. Unlike traditional design systems written for humans, agentic design systems encode intent, relationships and constraints as machine-readable context." — [Agentic Design Systems: The Complete Guide](https://www.intodesignsystems.com/agentic-design-systems)
- Figma resource page, publication date not on the page, cites "our 2025 AI report": "LLM context design means writing your design system down in a form that a model can reliably read and apply." It names three layers: a token layer, specs that state usage rules, and an audit loop. It maps those to context engineering as instructions, retrieved knowledge, and evaluation loops, and maps "Tool access" to Figma MCP. It also says Figma MCP gives a coding agent "direct access to your tokens, specs, and Code Connect mappings." — [LLM Context Design: Make Your Design System AI-Ready | Figma](https://www.figma.com/resource-library/llm-context-design/)
- Figma developer docs, undated in the fetch: "Code Connect UI lets you map design components in your Figma libraries to the corresponding code components in your repository. These mappings enhance the Figma MCP server by giving AI agents direct references to your code." The same docs describe an "Add instructions for MCP" field for props, accessibility, and team conventions. — [Getting Started with Code Connect UI](https://developers.figma.com/docs/code-connect/code-connect-ui-setup/)
- Figma, "Contextual AI coding," undated in the search snippet: Dev Mode, the Figma MCP server, and Code Connect "turn a coding agent's guesswork into something closer to what you'd actually ship." Code Connect "points an agent to the exact production component your team has already built, instead of letting the agent generate a lookalike from scratch." — [Contextual AI Coding: How Agents Use Design Context | Figma](https://www.figma.com/resource-library/contextual-ai-coding/)
- Schema 2025 recap, Paige Costello, VP Product, Figma, article date 28 October 2025: announces "the beta release of the Figma MCP server, which brings Figma directly into the developer workflow to help LLMs achieve design-informed code generation." The same URL, as returned in this November 2026 search, also says the server "is out of beta and generally available" and that teams can "add guidelines for how AI models should adhere to your design system." Those later sentences use "today" and may be page updates after 28 October 2025; page history was not diffed. — [Schema 2025: Design Systems For A New Era | Figma Blog](https://www.figma.com/blog/schema-2025-design-systems-recap/)
- Brad Frost, 16 December 2025: he and Storybook use "DS+AI" ("AI+DS" is rejected in the post as awkward). Storybook MCP "helps teams generate UI by wielding their sturdy, well-considered design system component libraries." Defining contrast: "This is what distinguishes DS+AI from vibe coding; the AI is deliberately constrained to using the high-quality design system materials to ensure what's being generated adheres to the organization's established standards." — [Agentic Design Systems in 2026 | Brad Frost](https://bradfrost.com/blog/post/agentic-design-systems-in-2026/)
- Chromatic session description, indexed as published 11 December 2025 (YouTube page not opened directly; see canonical-references section): "Autonomous agents are assembling UIs with the same components your human teams use. That shift demands design systems evolve into machine-readable infrastructure." Success conditions named in the description: coverage (examples, states, constraints) and validation (tests and human sign-off). — [Agentic Design Systems in 2026 with Brad Frost](https://www.youtube.com/watch?v=Vg78K3t9KYc) as reproduced by [Zolotube](https://zolotube.com/watch?v=Vg78K3t9KYc) and [Video Highlight](https://videohighlight.com/v/Vg78K3t9KYc)
- shadcn/ui docs, undated: "The shadcn MCP Server allows AI assistants to interact with items from registries. You can browse available components, search for specific ones, and install them directly into your project using natural language." This is a distribution API (registry JSON plus CLI), not a token-governance spec. — [MCP Server - shadcn/ui](https://ui.shadcn.com/docs/mcp)

It exposes component JSON at `/r/${component_name}.json` for v0 and says the shadcn CLI MCP command uses `registry.json`, including a `registry:theme` item that "contains your design tokens / CSS variables." — [shadcn/ui Registry Starter](https://vercel.com/templates/next.js/shadcn-ui-registry-starter)

- zeroheight marketing page, undated: "zeroheight MCP delivers your documented components, tokens and guidance straight to AI tools and agents, so they can create designs and code that follow your system from the start." #### Meaning B — a pattern library for designing agentic product UX

- Shape of AI, curated and written by Emily Campbell (about page; site launch date not stated): a public pattern library for "the UX of AI," grouped as Wayfinders, Prompt actions, Tuners, Governors, and Identifiers. Governors are "Human-in-the-loop features to maintain user oversight and agency," including Action plan, Controls, Stream of Thought ("Reveals the AI's logic thought process, tool use, and decisions"), Shared vision, Verification, Citations, and Cost estimates. The about page does not use the phrase "agentic design system." — [The Shape of AI](https://www.shapeof.ai/), [About](https://www.shapeof.ai/about), [Governors](https://www.shapeof.ai/pattern-types/governors)
- Emily Campbell, "Designing beneath the surface: The layers of AiUX," 4 June 2026, originally at emilycampbell.co: "Agentic UX is emerging as a discipline in itself because these systems often involve multiple coordinated processes operating across layers of autonomy." She defines agents as "autonomous systems that combine skills, tools, and data access, pointed at specific goals." Her layer model is User interfaces, Context, Harness, Model, Governance, and Emergence. This is a UX-systems essay, not a component-library spec. — [Designing beneath the surface: The layers of AiUX](https://shapeofai.substack.com/p/designing-beneath-the-surface-the)
- Shape of AI pattern pages (undated) spell the interaction objects people mean by "chat, tools, handoff, confidence" without using the design-system phrase. Stream of Thought: "Show the plan before you act... Separate plan, execution, and evidence." Workflow: distinguish "User-authored" steps from "AI-reported" steps, and keep "authoring mode" vs "reporting mode." Shared vision: ambient cues for what the AI can see, plus scope limits. — [Stream of Thought](https://www.shapeof.ai/patterns/stream-of-thought), [Workflow](https://www.shapeof.ai/patterns/workflow), [Shared vision](https://www.shapeof.ai/patterns/shared-vision)
- RAD, GitHub Pages site `jackiecurry/rad`, no author name or date on the fetched page: "RAD (Responsible, Accountable, Disclosed) is a design system for responsible agentic experiences — with reusable patterns, components, and guidance for disclosure, oversight, recovery, and accountability." Named components include Agent Activity Timeline, Human Approval Gate, Tool Execution Log, Source Trace, Confidence Display, and Agent State Indicator. Principle line on the page: "RAD components are not suggestions. They are design contracts — the minimum viable accountability layer for any agentic system." — [RAD · A Design System for Agentic Experiences](https://jackiecurry.github.io/rad/)
- NN/g, "Designing AI Agents: 4 Lessons from China's Qwen Agent," summary in search snippet, page not fetched in full: lessons are discoverability, reuse of familiar patterns, care with personal data, and user autonomy (review, edit, pay). This is product-UX research, not a design-system specification. — [Designing AI Agents - NN/G](https://www.nngroup.com/articles/designing-ai-agents/)
- arXiv abstract only, "From Conversation to Orchestration: HCI Challenges and Opportunities in Interactive Multi-Agentic Systems," June 2025 preprint id 2506.20091. The fetched abstract fragment discusses assigning roles, constraints, and monitoring in multi-agent interaction, and the balance of transparency and control. Full paper body was not used. — [arXiv:2506.20091](https://arxiv.org/abs/2506.20091)

#### Meaning C — agents author or maintain the design system

- zeroheight, same MCP page as above: "Connect your design system to every AI workflow, and maintain it with AI." "When documentation needs updating, agents can create and edit page content through MCP." Write is permissioned: "Only editors and admins can use MCP-Write." — [zeroheight MCP](https://zeroheight.com/mcp/), tool split confirmed in [zeroheight MCP tools reference](https://help.zeroheight.com/hc/en-us/articles/51478956166939-zeroheight-MCP-tools-reference) (read tools on every connection; write tools only for signed-in admins/editors)
- Supernova, undated marketing page: "If it speaks MCP, it can read the system and write back." "Create pages, edit tokens, restructure components, publish. Most design system MCPs stop at read." Example skills still gate publication: documenting a new component "Writes components, Figma links and unpublished pages in the shared draft after the user approves; never publishes." — [MCP for design systems | Supernova.io](https://www.supernova.io/mcp)
- Into Design Systems guide, attributed to Romina Kavcic's conference framing: a "self-healing loop" of "observe, detect, suggest, fix, learn," "based on IBM's 2003 MAPE-K framework." "Signals from Figma API, CI hooks and usage analytics flow into a drift-scoring engine that creates PRs automatically." Trust is graded: "Start as an intern (suggest only), then junior (mechanical fixes), then more autonomy. Some decisions will always need human judgment." The 2003 IBM framework is background for the loop metaphor, not a 2024–2026 definition of this phrase. — [Agentic Design Systems: The Complete Guide](https://www.intodesignsystems.com/agentic-design-systems)
- Same guide, on GitHub Primer as presented by Jan Six: "Agentic workflows run daily QA and maintenance with safe outputs, where an agent can only create an issue." That is maintenance with a hard ceiling, not authorship of components. — same URL
- Same guide, on Brad Frost, Ian Frost, and TJ Pitre: a Figma Console MCP demo in which "Create a new theme called Lavender" "rolls out new tokens to Figma, Storybook and React Native." That is an agent writing system foundations, as reported by the conference summary, not by a Frost primary post fetched here. — same URL
- Brad Frost, 18 November 2026: agent skills that "help you make better design systems" and "establish healthy limits for AI use." The `/ds-inspection` skill scores a system and returns "a detailed, prioritized plan" covering "quality, accessibility, parity, and AI readiness." He quotes TJ Pitre, early in their AI & Design Systems course: "You don't want to hitch rocket boosters to the back of a car with its check engine on." This is agents used to repair the system before they consume it. — [Skills to pay the bills | Brad Frost](https://bradfrost.com/blog/post/skills-to-pay-the-bills/)
- Mafalda Barata, IxDF meetup page for 19 November 2026 (event copy, not a transcript): "Lead Product Designer at OutSystems, who builds design systems for humans and agents to work together." At OutSystems, "Fusion Observatory, an agentic hub for our core design system... People and agents now work from the same source." The promised definition in the agenda: "What an agentic hub is." — [You Need an Agentic Design System Hub, If… with Mafalda Barata](https://ixdf.org/meetups/you-need-an-agentic-design-system-hub-if-with-mafalda-barata-nov-19th-2026)
- Figma LLM-context FAQ, undated page: "Can AI help build a design system from scratch, or does it only read one that already exists? Both. AI can help draft a first pass at components, especially with a tool like Figma Make." — [LLM Context Design | Figma](https://www.figma.com/resource-library/llm-context-design/)
- Figmalion issue note dated 2 May 2026, secondary index, not a Figma primary page: describes `useFigma` as "the new write-capable MCP tool that creates real components, variables, and auto layout on the canvas, not flat images or wireframes," and quotes Figma positioning "AI designs with you, not instead of you." — [Videos | Figmalion](https://figmalion.com/type/videos/page/4)

#### Additional meanings that are in circulation and should not be folded into A–C

- Aestheria four-machine taxonomy, August 2026 field snapshot: traditional (human assembles from tokens, components, patterns), computational (`design = f(context, content, constraints)`), generative (a goal produces candidates a human chooses), agentic ("plans, chooses, builds, and evaluates"). The post insists these are a stack, not a succession: assets, then logic, then generation, then agency. "An agent without the logic layer beneath it is not a more advanced design system." Three agentic cells are marked "Unsolved" as of that post: explaining a decision at runtime, what verification runs against, and recourse when wrong. — [Aestheria](https://aestheria.design/blog/what-is-an-agentic-design-system)
- NN/g, Sarah Gibbons and Kate Moran, 10 April 2026, "AI Agents as Users": "user is no longer synonymous with human." Agents "navigate websites, fill out forms, compare options, and execute transactions." Three interaction modes: vision/screenshots, the accessibility tree, and direct API/MCP. The design recommendation is accessibility and predictable patterns so agents can operate the product. This is not a claim about design-system infrastructure. The article also lists reasons not to optimize for agents (the visit is the product, intentional friction, competitive data, wanting to be the agent layer yourself). — [AI Agents as Users - NN/G](https://www.nngroup.com/articles/ai-agents-as-users/)
- Prompt and skill files as a claimed layer of the system, not a separate public definition of the phrase but a recurring substitute. Into Design Systems: "AGENTS.md is an orchestration file that tells AI agents how to work with your design system" and sits with "always-on rules" plus "MCP on-demand." Brad Frost's November 2026 skills repo is installed with `npx skills add bradfrost/skills`. Astryx generates "agent docs" via CLI. Figma Code Connect stores "instructions for MCP" per component. None of these pages call the prompt file itself the design system. — [Into Design Systems](https://www.intodesignsystems.com/agentic-design-systems), [Brad Frost](https://bradfrost.com/blog/post/skills-to-pay-the-bills/), [Astryx](https://astryx.atmeta.com/docs/working-with-ai), [Code Connect UI](https://developers.figma.com/docs/code-connect/code-connect-ui-setup/)
- "AI-native" as a distribution claim. Vercel/shadcn Registry Starter uses "AI-Native Design System" for a registry an agent can install from. Astryx uses "agent ready" for a versioned React package plus CLI. These overlap Meaning A but stress installable code over documented governance. — [Vercel template](https://vercel.com/templates/next.js/shadcn-ui-registry-starter), [Astryx](https://astryx.atmeta.com/)

### Inferences

- Meaning A is the dominant public use among design-system vendors and design-system leads from late 2025 through November 2026. Meaning B is older as a practice (Shape of AI's pattern site) and rarely uses the exact phrase; RAD is the clearest case of someone calling a pattern library for agent UX "a design system." Meaning C is real in product copy (zeroheight, Supernova, Figma's write paths) but is usually described as a permissioned write-back, not as the system becoming autonomous.
- Aestheria's taxonomy is the sharpest split inside Meaning A: most vendors mean "an external agent can read our system." Aestheria also uses "agentic" for the system itself making and checking decisions, and says that without a computational rule layer this is only generation.
- "Agents as users" (NN/g, April 2026) will be misread as Meaning A if later research is not careful. It is about the shipped product interface, not about the design system as an artifact.

### Gaps

- No source in this pass establishes who first printed the exact phrase "agentic design system," or a 2024 primary that already used it. The earliest dated public hits found here are late 2025 (Schema recap 28 October 2025 for the Figma MCP mechanism; Chromatic/Frost December 2025 for the phrase in a title).
- Figma's "LLM context design" and "Contextual AI coding" pages, Shape of AI's pattern site, RAD, Snapflow, Josef Richter, Carbon, Helios, Knapsack, Serendie, zeroheight, Supernova, shadcn MCP docs, and Code Connect docs did not expose a publication date in what was retrieved.
- The Into Design Systems page is a conference summary. Speaker statistics (Indeed's 1,056 prompts, 77 components, 4,300 prototypes, JSON vs Markdown token cost; Spotify Encore's 220,000 style uses and 93% satisfaction; "28 frontier models," "$200B+," "100k → 8M+ MCP downloads") were not checked against talk transcripts or the organizations' own write-ups.
- Astryx's open-source date conflicts across secondary pages: Aestheria says "in June 2026 Meta released Astryx"; InfoQ's story URL is September 2026 ("recently announced"); a later commentary says posts on 8 November 2026. The Astryx site itself only says beta and "eight years" internal. The June date is not verified from a Meta primary page here.
- Anthropic, Microsoft Fluent, Adobe Spectrum, Google Material, Clarity, WWDC, Google I/O, and AI Engineer were not found, in these searches, publishing a definition of "agentic design system." Absence is a search result, not proof they never did.

## Who coined or popularized each meaning?

### Takeaway

There is no verified coiner of the phrase. What can be sourced is who put a definition or a mechanism in public, and when. Meaning A was popularized in the design-systems community by Figma's MCP work (Schema 2025), Brad Frost with Storybook/Chromatic (December 2025, "DS+AI"), then by a 2026 conference cluster (Romina Kavcic / Into Design Systems, Diana Wolosin / Indeed, Jan Six / GitHub, Jesse Gardner / New York State, Brad Frost again) and by vendor MCP products (Carbon, Helios, Knapsack, zeroheight, Supernova, shadcn, Serendie, Astryx). Meaning B was popularized as AI UX patterns by Emily Campbell's Shape of AI, with RAD as a later named "design system for agentic experiences," and NN/g covering agent-product research in 2026. Meaning C is popularized as product behavior by zeroheight and Supernova, and as a conference idea ("self-healing," trust levels, agents that open issues or PRs) by Romina Kavcic's Into Design Systems synthesis.

## Where do practitioners disagree?

### Takeaway

The live disagreements are not about whether agents should see the design system. They are about what the system actually is (a library, a rule engine, a registry of code, a prompt file), what form is authoritative (tokens, component JSON, Code Connect mappings, Markdown docs, package source), whether the agent may write back, and whether "agentic" means the system has agency or only that an outside agent can read it. Several well-known numbers in this debate are conference retellings, not primary measurements.

### Cited Findings

Design system vs tokens vs component APIs vs prompt files:

- Figma's undated LLM-context essay says tokens are "the first thing a model reads," but a token layer without usage rules fails: a model will pick a default variant because "nothing in the code says when to use each." The audit loop is a third, separate layer. Prompting is treated as insufficient on its own: the page says teams over-invest in "prompts and rules files" in the sibling "contextual AI coding" essay, and that design context is the missing input. — [LLM context design](https://www.figma.com/resource-library/llm-context-design/), [Contextual AI coding](https://www.figma.com/resource-library/contextual-ai-coding/)
- Into Design Systems, attributing Diana Wolosin: "JSON is like a contract. It has explicit keys, explicit values, explicit boundaries, and there is no ambiguity." The guide's paraphrase of her rule: "JSON for MCP and Markdown for LLM." Component APIs, props, sizes, and variants belong in JSON; natural-language instructions can stay in Markdown. The same page says MCP is on-demand, so foundations (spacing, color, typography) must be "always-on rules," with AGENTS.md as the orchestration file. That is an explicit three-way split: token/foundation rules, component contracts, and prompt files, none sufficient alone. — [Into Design Systems](https://www.intodesignsystems.com/agentic-design-systems)
- Jan Six, as quoted there: semantic names such as `danger.background`, "not raw red-500," plus front-matter so docs are parseable. Tokens without semantic names are treated as a failure mode. — same URL
- Aestheria, August 2026: "Not design tokens as a list of hex values, but as a set with edges. Not a usage guideline as a paragraph, but as a condition a build can break on." A documentation platform "make[s] an existing design system readable"; that is different from shipping "judgment" (when to confirm, when a table beats cards, when density should drop). "A component inventory cannot answer those. A rule set can." — [Aestheria](https://aestheria.design/blog/what-is-an-agentic-design-system)
- shadcn/Vercel: the thing the agent installs is registry code (components, blocks, a theme of CSS variables). The docs do not describe a verification contract or a closed token set. — [shadcn MCP](https://ui.shadcn.com/docs/mcp), [Registry Starter](https://vercel.com/templates/next.js/shadcn-ui-registry-starter)
- Astryx docs: the authoritative interface for an agent that can run commands is the CLI against the installed package version; hosted MCP is docs for "the latest published release, not for your project," and is for tools that cannot run commands. A secondary article (not Meta) argues this yields a version skew between CLI and hosted MCP. — [Astryx docs](https://astryx.atmeta.com/docs/working-with-ai), [ai.satyajit.si commentary](https://ai.satyajit.si/articles/astryx)
- iMasters snippet, citing Kaelig Deloumeau-Prigent, July 2026, not independently opened: 20 of 21 open-source systems had an MCP, and only 3 had Code Connect. The article's point: "far more systems let AI read them than systems that manage to tie their components back to the design." If true, the community has standardized the pipe faster than the design-to-code link. Unverified beyond that snippet. — [iMasters](https://imasters.com/design-ux/ai-automates-the-easy-part-of-design-systems-but-governance-remains-human)

Deterministic system vs stochastic model:

- Into Design Systems: "MCP is deterministic, LLM is stochastic. The same MCP query returns the same data, but the LLM reasons differently each time." — [guide](https://www.intodesignsystems.com/agentic-design-systems)
- Snapflow asserts a stronger product claim: same intent, same screen, same code, "whoever asks for it," and "The adherence check runs in CI with no model involved." That is a vendor promise, not a measured result. — [Snapflow](https://www.snapflow.design/en/blog/agentic-design-system.html)
- Nathan Curtis, episode page 23 July 2026: structured extraction from Figma, and a caution "against using agents where deterministic processes are more precise." His 2 May 2026 LinkedIn post splits every report into a scripted layer and an agentic layer. — [podcast](https://podcast.wakeupexcited.show/26), [LinkedIn](https://www.linkedin.com/posts/nathanacurtis_what-if-you-could-audit-an-entire-design-activity-7456291792762748928-LfNk)
- Aestheria marks "Verified against" for the agentic column as "Unsolved" in August 2026, and says an agent that reviews its own output "has agreed with itself" unless the check is an external computational standard. — [Aestheria](https://aestheria.design/blog/what-is-an-agentic-design-system)

Who may change the system:

- Helios: read-only, does not modify the project. — [Helios](https://helios.hashicorp.design/tooling/mcp-server)
- Carbon and Knapsack, as documented: access to current system content, no write tools described on the pages fetched. — [Carbon](https://www.carbondesignsystem.com/getting-started/carbon-mcp/overview), [Knapsack](https://docs.knapsack.cloud/intelligent-tools/mcp-server)
- GitHub/Jan Six, via the conference guide: the agent "can only create an issue." — [Into Design Systems](https://www.intodesignsystems.com/agentic-design-systems)
- zeroheight: editors and admins may write styleguide pages; viewers are read-only. — [zeroheight](https://zeroheight.com/mcp/)
- Supernova: agents may create and edit, but the documented skills "never publish" without approval. — [Supernova](https://www.supernova.io/mcp)
- Romina Kavcic, via the guide: trust levels from suggest-only, to draft PR, to auto-merge, and "Some decisions will never go past level three." — [Into Design Systems](https://www.intodesignsystems.com/agentic-design-systems)
- Josef Richter: the agent proposes a contract change and "does not rewrite the rule just to make its output pass." Governance "reviews proposals before the system changes." — [Josef Richter](https://josefrichter.design/ai-design-systems/)
- Brad Frost, 18 November 2026: use agents to inspect and improve a weak system, and do not "hook AI rocket boosters up to a design system that's rickety." 16 December 2025: generation is allowed only inside "high-quality design system materials," as against "vibe coding." — [18 November 2026](https://bradfrost.com/blog/post/skills-to-pay-the-bills/), [16 December 2025](https://bradfrost.com/blog/post/agentic-design-systems-in-2026/)

What "agentic" is allowed to mean:

- External reader (Figma, Carbon, Helios, shadcn, Frost's DS+AI): the agent is a new consumer of a human system.
- System-with-agency (Aestheria taxonomy): the agentic layer "plans, chooses, builds, and evaluates," and is not the same machine as a generative system that only offers candidates.
- Self-healing infrastructure (Into Design Systems): the system plus agents observe drift and propose fixes.
- Pattern language for agent UX (Shape of AI, RAD, NN/g agent articles): the object being designed is the agent's behavior in the product, not the component library.
- Agents as a second user of the finished UI (Gibbons and Moran, 10 April 2026): accessibility and semantics, or a deliberate refusal to let agents in. — [NN/g](https://www.nngroup.com/articles/ai-agents-as-users/)

Package truth vs documented decisions:

- Astryx's own docs generate context from the package and tell the agent not to invent props or use raw values. — [Astryx](https://astryx.atmeta.com/docs/working-with-ai)
- A commentary that is not Meta's, Nervegna's Substack, argues Astryx skips hand-maintained Storybook stories, while Storybook MCP and zeroheight still depend on a site humans maintain, and that Astryx therefore cannot hold a company's bespoke usage rules. Useful as a disagreement in the discourse; the "open sourced in June" line in that post is one of the conflicting Astryx dates and should not be treated as Meta's date. — [Nervegna](https://nervegna.substack.com/p/your-storybook-is-a-museum-nobody)
- Aestheria makes the same structural point without picking Astryx as the winner: context (what exists) is not judgment (what good looks like here). — [Aestheria](https://aestheria.design/blog/what-is-an-agentic-design-system)

Human documentation is not agent documentation:

- Figma: "Human documentation gets away with a lot of shorthand... A model doesn't have that context, so it has to be written into the token." — [Figma](https://www.figma.com/resource-library/llm-context-design/)
- Wolosin, as quoted in the conference guide: the design system "needs to be in a format that the AI can understand." The guide paraphrases a benchmark in which Markdown used far more tokens and hallucinated more than JSON. Those measurements are not re-verified here. — [Into Design Systems](https://www.intodesignsystems.com/agentic-design-systems)
- Jan Six, same page: if the agent cannot see the invisible part of the system, "it has to hallucinate."

### Inferences

- "Just expose MCP" and "just publish tokens" are both minority positions among the definitional essays. The essays that try to define the phrase (Aestheria, Into Design Systems, Figma's LLM-context piece, Frost) all say the agent needs a constraint it cannot satisfy by improvising: a contract, a usage rule, a test, or a human gate.
- The sharpest naming dispute is Aestheria versus the vendors. Vendors can call a read-only MCP an agentic or agent-ready design system. Aestheria says that is at most the lower layers of the stack, and that verification and recourse were still unsolved in August 2026.
- Meaning B and Meaning A will be argued past each other if a team uses one phrase for both the component pipeline and the chat/handoff UI. The sources themselves rarely cross-cite. Shape of AI does not cite Figma MCP. Figma's LLM-context page does not cite Shape of AI or RAD.

- Snapflow's determinism claim and Indeed's JSON-vs-Markdown cost claim are the two quantitative disagreements most likely to be repeated. Neither was checked against a method section or a dataset.
- Storybook maintainers' own words on whether stories, MCP, or tests are the source of truth were not opened; only Frost's account and third-party descriptions were.
