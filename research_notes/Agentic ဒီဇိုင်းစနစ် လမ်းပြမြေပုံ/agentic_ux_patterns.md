# Agentic product UX patterns

Research pass completed 21 November 2026. Claims below are limited to pages fetched or indexed in this pass. Pre-2024 material is marked as background. Pattern names are only those printed by the cited source.

## What pattern collections exist, with the pattern set, date, and URL?

### Takeaway

By November 2026 the field has several overlapping catalogs rather than one shared library: an independent pattern site (Shape of AI), vendor principle sets (Microsoft HAX and the April 2025 Agent UX principles, Google’s People + AI Guidebook, Anthropic and OpenAI interface rules), usability research (Nielsen Norman Group, 2026), and public design systems that shipped AI-specific components or writing rules (IBM Carbon, Adobe React Spectrum, Amazon Cloudscape, Salesforce Lightning Design System 2). Shopify Polaris and GitHub Primer did not yield an official AI-component page in this pass.

### Cited Findings

- **Shape of AI**, live library at [The Shape of AI](https://www.shapeof.ai/). The homepage fetch did not show an author name or a publication date. A Dive Club interview dated 24 November 2025 identifies Emily Campbell as the creator and treats the site as an active pattern database ([shape of ai](https://dive-club.beehiiv.com/p/new-post-0961), Ridd / Dive Club). A secondary write-up also attributes the library to Emily Campbell, VP of Design at Hackers/Founders ([Shape of AI: A Pattern Library for AI UX Design](https://amirelion.com/blog/shape-of-ai-pattern-library-ai-ux-design), Amir Elion; date not on the indexed page).
- Patterns rendered on the Shape of AI homepage in this pass, grouped by the site’s own headings ([The Shape of AI](https://www.shapeof.ai/)):
  - **Wayfinders:** Example gallery, Follow up, Initial CTA, Nudges, Prompt details, Randomize, Suggestions, Templates.
  - **Prompt actions:** Auto-fill, Chained action (name only; no description rendered), Describe, an unnamed “lengthen” action, Inline Action, Inpainting, Madlibs, Open input, Regenerate, Restructure, Restyle, Summary, Synthesis, Transform.
  - **Tuners:** Attachments, Connectors, Filters, Model management, Modes, Parameters, Preset styles, Prompt enhancer (name only), Saved styles, Voice and tone.
  - **Governors:** Action plan (“show the steps it will take … before it executes”), Branches, Citations. The rendered Governors block stopped there.
  - **Trust builders:** Footprints was the only name rendered.
  - **Identifiers:** Color, Iconography, plus two described but untitled items (how the AI is named, and personality).
- Amir Elion’s secondary catalog adds governor and trust names that did **not** render on the homepage fetch: verification prompts, pause or redirect mid-stream, cost estimates, stream-of-thought, caveats, data ownership, disclosure labels, incognito, avatars, naming, personality ([Shape of AI: A Pattern Library](https://amirelion.com/blog/shape-of-ai-pattern-library-ai-ux-design)). Treat those names as his summary, not as a second primary list, until each subpage is opened.
- **Microsoft HAX Toolkit**, [Design patterns](https://www.microsoft.com/en-us/haxtoolkit/design-patterns/) (Microsoft; page undated in the fetch; feature image path includes 2021). Patterns exist for eight of the guidelines. Each pattern uses Problem, Solution, When to use, How to use, User benefits, and Common pitfalls. The page says patterns are UI-independent and were derived from “hundreds of examples” plus research. Confirmed pattern examples in this pass: G1-A Introductory blurb, G1-B explanations, G1-C expose system controls, G1-D demonstrate possible inputs, G1-E show a set of outputs ([Make clear what the system can do](https://www.microsoft.com/en-us/haxtoolkit/guideline/make-clear-what-the-system-can-do/)); Copilot in PowerPoint uses an introductory blurb plus a “can make mistakes” disclaimer ([Copilot in PowerPoint | 1A](https://www.microsoft.com/en-us/haxtoolkit/example/copilot-in-powerpoint-1a-introductory-blurb/)); Windows Copilot uses work/web tabs and conversation style (creative, balanced, precise) as global controls ([Windows Copilot | G17](https://www.microsoft.com/en-us/haxtoolkit/example/windows-copilot-g17-provide-global-controls/)). **Background:** the HAX guideline set predates the 2024 agent wave; this pass did not re-fetch the original 18-guideline list.
- **Microsoft Copilot UX guidance for builders**, [Creating a dynamic UX: guidance for generative AI applications](https://learn.microsoft.com/en-us/microsoft-cloud/dev/copilot/isv/ux-guidance) (Microsoft Learn; date not in the indexed excerpt). Three frames: Immersive (full canvas), Assistive (in-app), Embedded (single entity). Principle 1 is “Human in control,” with the copy rule “Summarize with copilot” rather than “copilot, summarize.” First-run guidance points back to HAX: state what the system can do and how often it may be wrong.
- **Microsoft Agent UX Design Principles**, [UX design for agents](https://microsoft.design/articles/ux-design-for-agents/) (Microsoft Design, 11 April 2025; primary contributors Ruokan He, Jen Fox, Amanda Snellinger). Three groups: Agent (Space) — connecting not collapsing; easily accessible yet occasionally invisible; Agent (Time) — past/memory, nudging more than notifying, adapting; Agent (Core) — embrace uncertainty, and transparency, control, and consistency. The article says some capabilities, “such as memory systems,” are still under development and the principles are forward-looking. Multi-agent actions must stay visible and controllable “via dashboards, settings, or other log type UX.” Background agents need a user-facing on/off and a visible status.
- **Fluent 2 Responsible AI**, [Responsible AI](https://fluent2.microsoft.design/responsible-AI) (Microsoft Fluent 2; date not retrieved). Indexed guidance covers labeling and attribution, disclosing limitations and what happens next, and making AI presence and reasoning visible. This pass did **not** confirm a public Fluent component page that lists Copilot components. A secondary survey claims Copilot UI kits exist as a Figma tier and that `@fluentui-copilot` packages are code-adjacent rather than documented on the Fluent site ([Design Systems That Document AI](https://learn.thedesignsystem.guide/p/design-systems-that-document-ai), Romina Kavcic, date not retrieved; [25-ai-aware-patterns-and-conversational-ui.md](https://github.com/adamforrester/knowledge-base/blob/main/25-ai-aware-patterns-and-conversational-ui.md)). Those claims are not treated here as official Fluent documentation.
- **Google People + AI / PAIR**, [People + AI Guidebook](https://pair.withgoogle.com/guidebook) and [Chapters](https://pair.withgoogle.com/guidebook/chapters). The guidebook URL returned an empty body in this pass (client-rendered). The search index of those URLs shows a pattern set organized by guiding questions (getting started, when to use AI, onboarding, explanation, datasets, calibrated trust, control versus automation, failures) and updated chapters: Data + Model Evolution, Mental Models + Expectations, Trust + Explanations, Feedback + Control, Errors + Graceful Failures. Mahima Pushkarna announced an official generative-AI update of the guidebook, describing six updated chapters, five new principles, and a new site, after “two years of development and testing with over 200 startups” ([LinkedIn post](https://www.linkedin.com/posts/mahimapushkarna_people-ai-guidebook-activity-7373772371352141824-ltRC); post date not parsed). **Background:** the original six-chapter guidebook is pre-generative; a PAIR Medium piece describes the editorial problem of hallucinations, fact-checking, and explanations ([Updating the People + AI Guidebook in the age of generative AI](https://medium.com/people-ai-research/updating-the-people-ai-guidebook-in-the-age-of-generative-ai-cace6c846db4)). The five new principle names were not retrieved.
- **Anthropic, conversation UI rather than protocol internals.** [Design guidelines](https://claude.com/docs/connectors/building/mcp-apps/design-guidelines) (Anthropic; date not on the fetched page) tells builders of in-conversation interfaces to split work: direct manipulation, filtering, confirmations, and visualization stay in the embedded UI; free text, clarification, redo, and navigation go back to the chat composer. An inline card auto-fits height, has no nested scrolling, at most two actions, at most four or five data points, and no menus, drill-ins, or multiple views. [What are artifacts and how do I use them?](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them) (Claude Help Center) defines an artifact as a substantial, self-contained output that opens beside the conversation when it is typically over 15 lines and likely to be edited or reused. [Citations](https://platform.claude.com/docs/en/build-with-claude/citations) (Anthropic) describes user-visible citation spans tied to document location (PDF page range, text character range, or custom block range). The cookbook prompt for a citations agent says cite substantive claims, prefer the end of a sentence, and avoid redundant nearby citations ([citations_agent.md](https://github.com/anthropics/anthropic-cookbook/blob/main/patterns/agents/prompts/citations_agent.md)).
- **OpenAI.** [UI guidelines](https://developers.openai.com/plugins/concepts/ui-guidelines) (OpenAI; date not on the indexed page) uses the same inline-card versus fullscreen split: cards for one decision or a small structured payload, at most two actions, no nested scrolling, no deep navigation; fullscreen keeps the composer and uses a shimmer while a response streams. Accessibility rules named there: WCAG AA contrast, alt text, text resizing. [Introducing canvas](https://openai.com/index/introducing-canvas/) (OpenAI; date not in the retrieved excerpt — treat as 2024-era background unless re-dated) describes a side-by-side writing and coding surface, highlight-to-edit, inline suggestions, and a back button to restore earlier versions. [Introducing ChatGPT agent](https://openai.com/index/introducing-chatgpt-agent/) (OpenAI, 17 July 2025) says the agent requests permission before actions of consequence, supports interrupt, browser takeover, and stop, uses “Watch Mode” for tasks such as sending email, and refuses high-risk tasks such as bank transfers. **The fetched page is labeled “This launch post is outdated.”** Those controls are July 2025 statements, not a reconfirmed November 2026 spec.
- **Nielsen Norman Group, 2026 research articles** (not a named component library):

The ten guidelines are: consolidate AI chat with other chat, keep it reachable across pages, state capabilities in the intro and suggested prompts, offer suggested questions as buttons, include images, use progressive disclosure, do not autoscroll to the end of a response, allow resize, allow save or share, consider voice input.
  - [Less Chat, More Answer](https://www.nngroup.com/articles/less-chat-more-answer/) — NN/g; date not retrieved. Argues for a “truncated pyramid”: essential answer first, extra detail behind follow-up prompts; no pleasantries.
  - [The 5 Dimensions of Site-Specific AI Chatbots](https://www.nngroup.com/articles/dimensions-of-ai-chatbots/) — NN/g; date not retrieved. Dimensions: handoff willingness, flexibility, proactivity (clarification and directional), emotional responsiveness, transparency (identity, capability, rationale, data).
  - [Prompt Suggestions](https://www.nngroup.com/articles/prompt-suggestions/) — NN/g; date not retrieved. Three types: use-case suggestions, autocomplete, follow-up questions.
  - [AI Chat Is Not (Always) the Answer](https://www.nngroup.com/articles/ai-chat-not-the-answer/) — NN/g; date not in the excerpt. Treat the publication date as unverified; do not assume it is a 2026 finding.

## Which patterns are treated as stable by late 2026, and which are still contested?

### Takeaway

Late 2026 sources treat capability disclosure, suggested prompts, streaming with a stop control, citations or a source list, approval before hard-to-undo actions, undo for reversible edits, and explicit loading and error states as expected. What remains contested is chat as the primary interface, how much reasoning and which sub-agents to show, whether confidence is a percentage, whether every action needs a dialog, and how streaming should be announced to assistive technology.

### Cited Findings

**Treated as expected, with sources that agree on the behavior**

- **Empty state and capability disclosure.** NN/g’s March 2026 study found participants rarely noticed site chatbots and could not tell what they were for; vague “ask me anything” copy over-promised ([What Is Your Site's AI Chatbot for?](https://www.nngroup.com/articles/site-ai-chatbot/), 20 March 2026). The April 2026 guidelines require an introductory message that names topics and suggested prompts as buttons ([10 Guidelines](https://www.nngroup.com/articles/ai-chatbots-design-guidelines/), 24 April 2026). Shape of AI groups the same job under Wayfinders: Suggestions, Templates, Example gallery, Nudges ([shapeof.ai](https://www.shapeof.ai/)). Cloudscape’s support prompt group can either send immediately or fill the composer for editing, and the placeholder copy is “Ask a question” ([Generative AI chat](https://cloudscape.design/gen-ai/patterns/generative-ai-chat/), 20 November 2024). Salesforce requires a welcome, examples, scope, and the sentence “I may make mistakes, so review my responses for accuracy.” ([AI agent design tips](https://www.salesforce.com/blog/ai-agent-design-tips/)). HAX G1 is the background pattern this later guidance still points at ([Make clear what the system can do](https://www.microsoft.com/en-us/haxtoolkit/guideline/make-clear-what-the-system-can-do/)).
- **Streaming responses plus a visible stop.** Spectrum exposes `isGenerating` on `PromptField` and `PixelLoader` inside `ResponseStatus` while work is in progress ([AI Components](https://react-spectrum.adobe.com/ai-components)). OpenAI’s fullscreen rules say the composer “shimmers” while a response streams ([UI guidelines](https://developers.openai.com/plugins/concepts/ui-guidelines)). Cloudscape requires loading states and points regenerate and stop to a separate pattern ([Generative AI chat](https://cloudscape.design/gen-ai/patterns/generative-ai-chat/)). Accessibility writers in 2025 treat streaming as the default visual behavior and argue only about the announcement, not about whether text should stream ([When AI Never Stops Talking](https://a11ypatterns.org/index.php?r=%2Fpatterns%2Fai-streaming-response), a11ypatterns, 29 July 2025).
- **Tool-call traces, as a collapsible record rather than the main reading surface.** Spectrum’s `ExecutionTrace` / `ExecutionTraceItem` is a timeline inside `ResponseStatusPanel`, with expandable detail “such as tool call input or output” ([AI Components](https://react-spectrum.adobe.com/ai-components)). Luke Wroblewski’s 24 November 2025 layout puts instructions, thinking traces, and tool calls in one column and results in another, then collapses the traces into a summary that can be reopened, with each step linking to its result ([Agentic AI Interface Improvements](https://www.lukew.com/ff/2136/agentic-ai-interface-improvements)). Kamushken’s “tool call cards” and “live step ledger” describe the same split, and he says identical consecutive calls should collapse ([16 AI agent UI design patterns](https://www.setproduct.com/blog/ai-agent-ui-design-patterns), 21 September 2026). Shape of AI’s Action plan is the before-execution version of the same idea ([shapeof.ai](https://www.shapeof.ai/)).
- **Plan, then act, for consequential work.** Shape of AI Action plan: show steps before execution ([shapeof.ai](https://www.shapeof.ai/)). Yocco’s Intent Preview is a plain-language sequence with Proceed, Edit Plan, and Handle it Myself, and he says it is non-negotiable for irreversible, financial, or shared actions ([Designing For Agentic AI](https://www.smashingmagazine.com/2026/02/designing-agentic-ai-practical-ux-patterns/), 11 February 2026). OpenAI’s July 2025 agent post says permission is requested before actions of consequence ([Introducing ChatGPT agent](https://openai.com/index/introducing-chatgpt-agent/), 17 July 2025; page now marked outdated).
- **Human approval, scoped to risk.** The same three sources above. Kamushken’s later catalog makes the scope explicit: read actions need no prompt, writes can be allowed for a session, destructive actions ask every time and have no “always allow” ([16 AI agent UI design patterns](https://www.setproduct.com/blog/ai-agent-ui-design-patterns), 21 September 2026). Yocco’s Autonomy Dial is the settings version of that tiering (same Smashing article).
- **Citations.** Shape of AI lists Citations under Governors ([shapeof.ai](https://www.shapeof.ai/)). Cloudscape specifies numbered inline markers `[1]`, `[2]`, `[3]`, a citation popover with the source title, and a Sources expandable section ([Generative AI chat](https://cloudscape.design/gen-ai/patterns/generative-ai-chat/)). Fluent’s Responsible AI page asks for source verification and attribution ([Responsible AI](https://fluent2.microsoft.design/responsible-AI)). Carbon’s explainability popover is the IBM equivalent of “where did this come from,” attached to the AI label ([Carbon for AI](https://www.carbondesignsystem.com/building-blocks/foundations/carbon-for-ai), updated 12 August 2026). Anthropic’s citations API returns location-level spans ([Citations](https://platform.claude.com/docs/en/build-with-claude/citations)).
- **Undo for reversible output.** Carbon: after the user edits AI-suggested content, the component leaves the AI visual style and a “revert to AI” button restores the generated value ([Carbon for AI](https://www.carbondesignsystem.com/building-blocks/foundations/carbon-for-ai)). Yocco’s Action Audit & Undo includes a time window when undo will expire ([Designing For Agentic AI](https://www.smashingmagazine.com/2026/02/designing-agentic-ai-practical-ux-patterns/), 11 February 2026). Canvas documents a back button for previous versions ([Introducing canvas](https://openai.com/index/introducing-canvas/)). Kamushken distinguishes per-action undo from a single checkpoint restore, and says no coding agent he watched had cleared per-action undo ([16 AI agent UI design patterns](https://www.setproduct.com/blog/ai-agent-ui-design-patterns), 21 September 2026).
- **Loading, empty, and error states.** Cloudscape: show processing status, do not autoscroll while the user is reading older messages, and follow error-message guidelines ([Generative AI chat](https://cloudscape.design/gen-ai/patterns/generative-ai-chat/)). Microsoft’s agent principles: “Agent status, or what the agent is doing, is clearly visible at all times” ([UX design for agents](https://microsoft.design/articles/ux-design-for-agents/), 11 April 2025). NN/g: do not autoscroll the user to the end of a response (guideline 7, [10 Guidelines](https://www.nngroup.com/articles/ai-chatbots-design-guidelines/), 24 April 2026). Yocco treats the error message as the apology: acknowledge, state the correction, offer a human path ([Designing For Agentic AI](https://www.smashingmagazine.com/2026/02/designing-agentic-ai-practical-ux-patterns/)).
- **Generative UI beside the transcript.** Anthropic artifacts open beside chat for documents, code, diagrams, dashboards, and small tools ([Artifacts help](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them); [Artifacts feature page](https://claude.com/features/artifacts)). OpenAI canvas is the same move for writing and code ([Introducing canvas](https://openai.com/index/introducing-canvas/)). Salesforce primitives exist so a response can be a card, a list, or a date input instead of a paragraph ([Modular design](https://www.salesforce.com/blog/modular-design-benefits-agentforce/)). OpenAI and Anthropic both publish the inline-card constraints listed above. Spectrum’s thread can hold suggestions, alerts, and status, not only text ([AI Components](https://react-spectrum.adobe.com/ai-components)).

**Still contested**

- **Chat as the product surface.** NN/g, 20 March 2026: a chatbot that repackages search, filters, or navigation adds friction; users could not tell what site bots were for ([site AI chatbot](https://www.nngroup.com/articles/site-ai-chatbot/)). Smashing’s July 2025 article says chat is a slow way to express intent and that task controls (presets, sliders, canvases) are taking the foreground, citing Luke Wroblewski ([Design Patterns For AI Interfaces](https://www.smashingmagazine.com/2025/07/design-patterns-ai-interfaces/)). Kamushken opens with the claim that a 300-line transcript fails even when the task succeeded ([16 AI agent UI design patterns](https://www.setproduct.com/blog/ai-agent-ui-design-patterns), 21 September 2026). Cloudscape, Carbon AI Chat, and Spectrum still ship chat as a first-class pattern. The contest is whether chat is the shell or one component inside a task UI.
- **How much reasoning to show.** Luke Wroblewski collapses traces after the run and keeps them reopenable (24 November 2025, link above). A Rosenfeld Media talk summary of his “Designing AI Applications” session says there are two mindsets: people who want the thinking, and people who want the result ([Designing AI Applications](https://rosenverse.rosenfeldmedia.com/videos/designing-ai-applications); talk date not retrieved). Kamushken says reasoning stays collapsed, closed by default, and should be omitted for non-technical audiences; a decision the user must act on must not live inside the disclosure ([16 patterns](https://www.setproduct.com/blog/ai-agent-ui-design-patterns)). Microsoft says the level of certainty and the reasoning should be “visible and/or easily accessible” to avoid overreliance ([UX design for agents](https://microsoft.design/articles/ux-design-for-agents/), 11 April 2025). No source in this pass reports a user study that picks one default.
- **Approval on every step versus tiered autonomy.** Yocco warns that the Intent Preview is for significant actions, and the Autonomy Dial exists because risk varies (11 February 2026). Kamushken names “approval fatigue” as a live anti-pattern: after several Allow dialogs, users click through the destructive one (21 September 2026). OpenAI’s July 2025 post limited explicit confirmation to consequential actions and added Watch Mode for email, which is a middle position ([Introducing ChatGPT agent](https://openai.com/index/introducing-chatgpt-agent/)). An independent essay states the same tradeoff as a grid of cost versus reversibility, and warns that gating everything trains click-through ([Human-in-the-Loop UX Framework](https://www.stratenity.com/resources/01_evidence/insights/essays/aiux); date not retrieved).
- **Citation visual form.** Cloudscape standardizes numbered inline markers plus a popover and a Sources section (20 November 2024). Nancy Niu writes that inline citations broke reading flow at Salesforce scale and were moved to a popover or panel, trading immediate visibility for stable card height ([pageai](https://www.cnancyniu.com/pageai)). A teardown of ChatGPT describes publisher chips on the claim, a popover, and a Sources row ([ChatGPT Citations UX](https://aiuxplayground.com/teardowns/chatgpt/citations); author and date not retrieved). Anthropic’s cookbook prompt prefers citation at the end of a sentence rather than mid-phrase ([citations_agent.md](https://github.com/anthropics/anthropic-cookbook/blob/main/patterns/agents/prompts/citations_agent.md)). The need for a source is stable; the widget is not.
- **Confidence displays.** Yocco’s Confidence Signal includes a percentage example (“Confidence: 95%”), a scope sentence, and color or icon cues, and he ties the pattern to automation bias (11 February 2026). Kamushken rejects a single success tone and specifies a three-part footer — Verified, Assumed, Could not do — and says most products still leave “assumed” implicit (21 September 2026). Microsoft asks for the level of certainty without specifying a number (11 April 2025). The ChatGPT citations teardown says ship citations first and add confidence only with calibrated signals ([aiuxplayground.com citations teardown](https://aiuxplayground.com/teardowns/chatgpt/citations)). These are incompatible recipes, not a settled component.
- **Multi-agent coordination.** Microsoft, 11 April 2025: collaboration with other agents is visible through dashboards, settings, or logs, and knowledge, tools, and connections are transparent ([UX design for agents](https://microsoft.design/articles/ux-design-for-agents/)). Luke Wroblewski, 9 June 2025: kanban, dashboards, inboxes, task lists, and calendars can show many agents, but kanban implies dragging cards (undefined for a running agent), inboxes fail at high volume and interdependent work, and indented task lists hide relevant subtasks ([Agent Management Interface Patterns](https://www.lukew.com/ff/2106/agent-management-interface-patterns)). His context-management note says nested sub-agent context should be one combined link, not a chip per tool call ([Context Management UI](https://www.lukew.com/ff/2110/context-management-ui-in-ai-products)). AY Designs, 11 June 2026, says showing every sub-agent and hiding every sub-agent are both failures, and proposes parent-owned conversation, collapsible sub-agent cards, role labels, and a shared scratchpad ([multi-agent UX guide](https://www.aydesign.ai/blog/multi-agent-system-ux-design-guide-2026)). No design system in this pass ships a multi-agent component set.
- **Memory.** Microsoft’s April 2025 article says agents use memory to connect past events to the current task, and in the same piece says memory systems are under development and the principles are forward-looking ([UX design for agents](https://microsoft.design/articles/ux-design-for-agents/)). HAX “remember recent interactions” is pre-2024 background and was not re-verified here. Independent catalogs name a memory editor, forget control, and recall trace ([Agent-First Design Patterns](https://auxfirst.com/agent-first-design-patterns.html); date not retrieved). Those names were not found in Carbon, Spectrum, Cloudscape, or Fluent.
- **What “progress” looks like for long runs.** A YouTube explainer of Jakob Nielsen’s “Slow AI” argument says percent-complete bars fail for hour-scale tasks and recommends a run contract (time, cost, scope, definition of done), conceptual breadcrumbs, partial results, and “context reboarding” when the user returns ([Slow AI: User Control for Long Tasks](https://www.youtube.com/watch?v=pKIlYbXY_5c); video date not retrieved; Nielsen’s own article was not fetched, so this is the video’s account). Kamushken lists “fake progress” (a bar that hits 90% and stalls) as a 2026 anti-pattern and prefers “step 4 of an unknown number” plus elapsed time (21 September 2026). OpenAI’s July 2025 post says the user can ask for a progress summary or stop and keep partial results ([Introducing ChatGPT agent](https://openai.com/index/introducing-chatgpt-agent/)).

### Inferences

- “Stable” here means the behavior shows up in more than one primary design system or research article by late 2026. It does not mean a shared component name. “Citations,” “AI label,” “Sources,” and “explainability popover” are the same job with different names.
- Tool traces and plans are stable as information architecture (before / during / after) and contested as visual density.
- Confidence percentages are the clearest contested widget: a major magazine article recommends them, and a later practitioner catalog replaces them with a verified / assumed / skipped statement.

### Gaps

- No head-to-head user study in this pass comparing inline citations with a side panel, or a confidence percentage with a gaps footer.
- Nielsen’s original Slow AI article URL and date were not opened; only the YouTube paraphrase was.
- OpenAI’s current (post-July 2025) agent confirmation UI was not re-documented, because the launch post says it is outdated.
- ChatGPT’s citation chips are described by a teardown, not by an OpenAI design page found in this pass.

## How are these patterns packaged as a design system?

### Takeaway

The systems that actually package agent UX do four jobs: a component (or primitive) with an AI-specific name, a content rule, a motion or status rule, and an accessibility note. Tone of voice is strictest in Cloudscape and Salesforce. Motion is mostly “show that work started, then stop announcing it.” Carbon and Spectrum are the only two in this pass that publish both visual tokens and named code components for AI.

### Cited Findings

- **IBM Carbon (updated 12 August 2026)** packages AI as a style mode plus two custom components, not as a chat-only kit ([Carbon for AI](https://www.carbondesignsystem.com/building-blocks/foundations/carbon-for-ai)).
  - Components: AI label (Default and Inline; formerly AI Slug), explainability popover, “revert to AI” button, and AI-styled variants of existing Carbon components that must embed the label. Chat is a separate stable asset: `@carbon/ai-chat`, with `ChatCustomElement` and `ChatContainer` ([Using with React](https://chat.carbondesignsystem.com/tag/latest/docs/documents/Using_with_React.html); v1 announced by Anna Wen, 14 October 2025).
  - Tokens: new AI color and style tokens inside the existing themes; the page describes light, glow, and gradient so AI is distinguishable without a separate theme.
  - The fetched page says each AI component includes the label and popover. The enumerated list of which core components have an AI variant was truncated in the index and was not recovered.
  - Accessibility principle on that page: the user must be able to tell that AI is being used; the label is the marker and the popover is the first layer of explainability.
- **Adobe Spectrum** packages the conversation as composable components in `@react-spectrum/ai` ([AI Components](https://react-spectrum.adobe.com/ai-components)). The page does not state a release date.
  - Input: `PromptField` and `PromptTokenField` (text plus tokens), `PromptFieldToolbar`, `PromptFieldSubmitButton`, `PromptFieldVoiceButton`, attachment list and preview, `aiDisclaimer` rendered under the field.
  - Transcript: `Chat`, `Thread`, `ThreadItem`, `UserMessage`, `ThreadLoadMoreItem`.
  - Status and tools: `ResponseStatus` with title and panel, `ExecutionTrace` as a timeline of steps, `PixelLoader` while pending.
  - Suggestions and failures: `MessageSuggestionList`, `Alert`.
  - Motion: `PixelLoader` is the documented working indicator. No duration or easing spec was on the fetched page.
  - Accessibility: `ExecutionTraceItem` exposes `aria-label` and status, and the trace detail is optional. The page does not include a tone-of-voice section.
- **Amazon Cloudscape** packages one pattern page as components, writing, and accessibility together ([Generative AI chat](https://cloudscape.design/gen-ai/patterns/generative-ai-chat/), 20 November 2024).
  - Components named above (chat bubble through support prompt group).
  - Content: sentence case; no exclamation points; no “please,” “thank you,” ellipsis, or “e.g.”; present tense and active voice; device-independent verbs (“select,” not “click”); call the system a “generative AI assistant”; call replies “responses,” not “answers”; user action label is “submit”; placeholder “Ask a question” or “Ask a question or type "/" for more actions”; Sources is the exact heading; thumbs feedback has specified disabled-reason strings.
  - Motion and behavior: loading state required; do not autoscroll if the user is reading older messages; keep the composer pinned; inline actions stay visible without hover; at most about five inline actions, then an overflow menu. Regenerate and stop are delegated to another page that was not fetched.
  - Accessibility: `role="region"` with an `aria-label` on the bubble container; announce a new message with a visually hidden live region. That live-region instruction conflicts with the 2025 accessibility pattern below.
- **Salesforce** packages agent UX as content structure, naming, and primitives rather than a public component list ([AI agent design tips](https://www.salesforce.com/blog/ai-agent-design-tips/); [SLDS 2](https://www.salesforce.com/blog/what-is-slds-2/); [primitives](https://www.salesforce.com/blog/modular-design-benefits-agentforce/)).
  - Content skeleton: welcome, disclosure, example questions, scope, feedback or escalation.
  - Voice: “clear and conversational,” aligned to brand; disclosure stays in the welcome or under the input, not buried.
  - Visual: distinct agent avatars versus marketing icons; accessible color; legacy icons being phased out.
  - Components: unstyled primitives (card, text, button, input) composed per response. The posts do not name a public npm component for “plan” or “approval.”
- **Microsoft** packages principles and copy rules more than a single AI component library in the pages fetched. HAX patterns are explicitly UI-independent ([Design patterns](https://www.microsoft.com/en-us/haxtoolkit/design-patterns/)). Copilot guidance includes the verb-order rule “Summarize with copilot” ([UX guidance](https://learn.microsoft.com/en-us/microsoft-cloud/dev/copilot/isv/ux-guidance)). Agent principles add status visibility, on/off, and logs for background and multi-agent work ([UX design for agents](https://microsoft.design/articles/ux-design-for-agents/), 11 April 2025). Fluent Responsible AI adds labeling, attribution, and limitation disclosure ([Responsible AI](https://fluent2.microsoft.design/responsible-AI)). A public Fluent component catalog for those patterns was not found.
- **OpenAI and Anthropic** package layout rules for generated UI inside the conversation, not a general-purpose design system. Shared rules: inline card, max two actions, no nested scroll, no deep navigation; heavier work goes fullscreen or beside the thread; composer stays available ([OpenAI UI guidelines](https://developers.openai.com/plugins/concepts/ui-guidelines); [Anthropic design guidelines](https://claude.com/docs/connectors/building/mcp-apps/design-guidelines)). OpenAI adds WCAG AA contrast, alt text, and text resize. Anthropic adds a mobile and host-style-variable requirement on that same page.
- **Smashing / Yocco, 11 February 2026**, is a pattern article, not a component library. It does specify anatomy: Intent Preview needs plain-language steps and three actions (Proceed, Edit, Handle it Myself); Confidence Signal may be a percentage, a scope line, and an icon; undo must state when it expires ([Designing For Agentic AI](https://www.smashingmagazine.com/2026/02/designing-agentic-ai-practical-ux-patterns/)). The acceptance-rate targets in that article (for example “> 85%”) are labeled representative benchmarks, not measured results.

### Inferences

- If a team asks for “the agentic design system,” the concrete code they can cite today is Carbon’s AI label plus chat package, Spectrum’s `@react-spectrum/ai`, and Cloudscape’s generative-AI chat pattern. Everything else in this pass is principles, content rules, or an independent pattern name.
- Tone is part of the system only where a vendor wrote the strings. Cloudscape forbids courtesy words; Salesforce requires a fallibility sentence. Those are opposite instincts and both are published.
- Motion specs are thin. The documented motion is a loader, a shimmer, or a collapse of the trace. Easing, duration, and reduced-motion rules were not in the Carbon, Spectrum, or Cloudscape pages fetched, except where a third-party component kit claims `prefers-reduced-motion` (see accessibility).

### Gaps

- Carbon’s full list of core components that have an AI variant.
- Cloudscape pages for regenerate, stop, thinking, and authorized actions were named by a secondary survey and were not fetched.
- Fluent Copilot component names and any motion spec.
- SLDS 2 Agentic Experience Figma library: the Salesforce post said it was coming; this pass did not find the published library URL.
- No design-system page in this pass defines a component named for memory, multi-agent handoff, or a confidence percentage.

## What do talks and articles say fails when a chat box is bolted on?

### Takeaway

The failure mode repeated from 2025 into 2026 is not “chat is bad.” It is that a generic corner composer hides what the system can do, duplicates search and navigation, makes features undiscoverable, and then breaks again when the system starts calling tools, because a single scrolling transcript cannot show a plan, a running step, a permission, and a result at once.

### Cited Findings

- NN/g’s March 2026 study: participants rarely used site AI chatbots, often did not notice them, and could not see value beyond search, filters, or ChatGPT. Home Depot’s Magic Apron was small, unlabeled, and visually lost; one participant thought the launcher was a graphic. Turo’s bot opened with an “ask me anything” line and could not do the vehicle-finding job users tried. The article’s rule is to start from an unsolved problem, not to add a bot and watch the logs, and not to rebuild browsing as a conversation ([What Is Your Site's AI Chatbot for?](https://www.nngroup.com/articles/site-ai-chatbot/), Rosala, Kenderova, Kohler, 20 March 2026).
- The same study says a bot that leads with promotions is read as a sales channel, and that a bot does not have to cover the whole site. Discoverability fails when the only entry is a floating icon; the prompt should be specific to the page (“Not sure which plan covers you?”) rather than “How can I help you?”
- NN/g, 24 April 2026, adds mechanical failures inside the bolt-on panel: suggested prompts as plain text instead of buttons, answers that are only links, autoscroll that yanks the reader, no resize, no way to save or share ([10 Guidelines](https://www.nngroup.com/articles/ai-chatbots-design-guidelines/)).
- NN/g’s “Less Chat, More Answer” (date not retrieved) says users want an answer, not a conversation; “great question” lengthens the reply; the first message should hold only what was asked plus the caveat, with the rest behind a follow-up ([Less Chat, More Answer](https://www.nngroup.com/articles/less-chat-more-answer/)).
- Smashing, July 2025: conversational input puts the burden of articulating intent on the user; the indexed text says usability tests show people lost in typing and retyping, often 30–60 seconds for the input, and that chat is the wrong place when the work already has a surface (the autocomplete analogy: nobody puts autocomplete in its own section) ([Design Patterns For AI Interfaces](https://www.smashingmagazine.com/2025/07/design-patterns-ai-interfaces/)). Author of the Smashing piece was not in the excerpt; the chat argument is attributed there to Luke Wroblewski.
- Luke Wroblewski, 24 November 2025: once the model does extended reasoning and tool use, a chat column becomes a long monologue. In a narrow side panel the original instruction scrolls away while the model keeps working. His fix is a second column for results, then a collapsed process summary ([Agentic AI Interface Improvements](https://www.lukew.com/ff/2136/agentic-ai-interface-improvements)).
- Luke Wroblewski, 9 June 2025: managing several agents is a different interface (start, schedule, scrutinize, steer, stop, share). Dropping them into one chat does not answer which agent needs a human. He also notes each familiar substitute fails in a specific way (kanban drag, inbox overload, collapsed subtasks) ([Agent Management Interface Patterns](https://www.lukew.com/ff/2106/agent-management-interface-patterns)).
- His context-management write-up: flashing every tool’s context as a chip, then removing it when the next tool runs, was “jarring.” Nested agents make a chip-per-call approach collapse ([Context Management UI](https://www.lukew.com/ff/2110/context-management-ui-in-ai-products)).
- Rosenfeld Media’s summary of Wroblewski’s talk states the framing directly: designing AI applications is not about where to add chat; suggested prompts and citations matter, and separating process from results manages mental load ([Designing AI Applications](https://rosenverse.rosenfeldmedia.com/videos/designing-ai-applications)). Talk date not retrieved.
- Kamushken, 21 September 2026, lists anti-patterns he says were shipping that year: an infinite spinner with no step names; approval on every file write; a confident “tests passed” when tests were not run; using the chat log as the only audit trail; actions (install, send, write) that never appear on screen; a percent bar for unknown-length work ([16 AI agent UI design patterns](https://www.setproduct.com/blog/ai-agent-ui-design-patterns)).
- James Morris, 13 June 2025: a chatbot used to paper over a messy help center treats the symptom; chat also hides features that a visible filter would teach, because the user must already know the feature exists in order to ask ([No, your product doesn't need an AI chatbot](https://jmaris.me/jekyll/update/2025/06/13/AI-chatbots.html)).
- Microsoft Design, 11 April 2025, warns that agents “may have chat experiences but generally go beyond typical chatbots,” and that background operation without a log removes control ([UX design for agents](https://microsoft.design/articles/ux-design-for-agents/)).
- Config 2026, Craig Labenz (Google), “Design for the future of apps”: generative UI fails when the model’s content does not match the layout assumptions. In the Gen Latte example, question length, aspect ratio, and the number and length of multiple-choice options were unknown at design time, so headings truncated and options jumped from one word to a sentence ([YouTube](https://www.youtube.com/watch?v=PLZoD-LvZTw)). That is the bolt-on failure one step later: the team keeps a fixed card and lets the model fill it.
- YouTube, “Slow AI” (date not retrieved): hour-scale agent runs fail like 1970s batch jobs if the UI only shows a spinner. The video, summarizing Jakob Nielsen, asks for clarifying questions and a run contract before the long task, partial results during it, and a recap of the original request when the user comes back ([YouTube](https://www.youtube.com/watch?v=pKIlYbXY_5c)). Nielsen’s article was not opened.
- NN/g’s undated-in-excerpt article “AI Chat Is Not (Always) the Answer” uses LinkedIn’s follow-up-question chat as a case of AI aimed at a problem the product did not have ([AI Chat Is Not (Always) the Answer](https://www.nngroup.com/articles/ai-chat-not-the-answer/)). Publication date not confirmed in this pass.

### Inferences

- The 2026 NN/g articles are the strongest evidence that the corner chatbot still fails for ordinary sites, because they are user studies rather than design essays. The Wroblewski and Kamushken pieces are the strongest evidence that the same shell also fails for tool-using agents, because a transcript cannot hold plan, trace, permission, and diff.
- Generative UI is not an automatic fix. Labenz’s Config 2026 talk is specifically about generated controls whose content length was not known when the component was drawn.

### Gaps

- No transcript or URL was found for a Clarity conference talk, a Google I/O design talk, a Microsoft Build design talk, or an AI Engineer Summit talk on this question.
- The Kate Moran NN/g YouTube video “The AI Adoption Gap” ([YouTube](https://www.youtube.com/watch?v=WQDcf_v7ikk)) was indexed, but the retrieved transcript was too fragmentary to cite a claim.
- The “30–60 seconds” input-time figure appears only inside the Smashing excerpt’s paraphrase. The underlying test was not opened.
- Video upload dates for the YouTube items above were not retrieved.

## How do accessibility and trust requirements differ from a traditional component library?

### Takeaway

A traditional component library mostly has to expose name, role, value, contrast, and keyboard access for a control that changes when the user acts. An agent surface also changes by itself over time, may be wrong, and may act on other systems. The extra requirements are: announce status without reading every token, keep focus in the composer, put citations and uncertainty in text, label the speaker as a system, and give the user stop, undo, and a record of what changed.

### Cited Findings

- **Streaming is a new accessibility problem, not a new color.** a11ypatterns Pattern 04, published 29 July 2025: if the message is an assertive live region, a screen reader announces fragments. The documented alternative is to keep the message out of live regions, set `aria-busy` while it streams, and announce start and completion in a separate polite status. The page says this is a considered approach, not an established standard, and it maps the requirement to WCAG 2.2 SC 4.1.3 Status Messages. Focus should stay on the control ([When AI Never Stops Talking](https://a11ypatterns.org/index.php?r=%2Fpatterns%2Fai-streaming-response)).
- **Cloudscape contradicts that announcement recipe.** Its generative-AI chat page tells teams to announce any new message with a visually hidden live region, and to put `role="region"` plus an `aria-label` on the bubble container ([Generative AI chat](https://cloudscape.design/gen-ai/patterns/generative-ai-chat/), 20 November 2024). A traditional chat log can use `role="log"`; the W3C’s WCAG 2.2 working example demonstrates `role="log"` for a short human chat, not for token streaming ([Using role=log with chat conversation](https://www.w3.org/WAI/WCAG22/working-examples/aria-role-log/chatlog.html)). **Background:** that W3C example is a general chat demo, not an agent pattern.
- An accessibility guide aimed at AI chat lists WCAG 2.2 criteria that become load-bearing in a transcript: 4.1.3 status without moving focus, 2.1.1 keyboard for send, stop, regenerate, copy, and scroll, 4.1.2 name/role/value including who sent the message, 1.3.1 structure of rendered markdown, 2.4.3 focus stays in the composer, 2.2.1 the user can stop a long generation, 1.4.13 hover toolbars are keyboard reachable, 1.4.3 contrast of bubbles and disabled send ([Accessible AI Chat Interfaces](https://accessibility.build/guides/accessible-ai-chat); date not retrieved). The same guide says to stream into a non-live node and write “Response complete,” or the full short reply, once. It also says WCAG still applies: a chat feature is web content, and native apps are in scope of WCAG2ICT.
- A vendor guide lists the same three breaks: streams that never stop announcing, focus that jumps on every token, and mouse-only controls. It adds auto-scroll only when the user is already near the bottom, `prefers-reduced-motion`, and `role="alert"` on retry errors ([Accessible AI interfaces](https://slipstreamui.com/docs/guides/accessibility-ai); vendor docs, date not retrieved).
- **Color-only trust signals fail.** A River Group article says confidence bars, percentages, and tinted backgrounds are often visual-only, so a screen-reader user hears a bare claim that a sighted user sees marked uncertain. It also says markdown rendered inside a bubble often breaks heading order ([AI Accessibility: When Screen Readers Meet AI Interfaces](https://rivergroup.ai/insights/ai-accessibility-screen-readers-meet-ai); date not retrieved). Yocco’s Confidence Signal, which includes a green check and a yellow question mark (11 February 2026), would need a text equivalent to meet that critique. Spectrum’s `ExecutionTraceItem` status values (`failed`, `pending`, `success`) are at least data, not only color ([AI Components](https://react-spectrum.adobe.com/ai-components)).
- **Identity and limitation are part of the component, not the marketing page.** Apple’s guideline, as restated in an explainer video, is to say the feature is AI and not let people think they are talking to a human; the video also cites Microsoft HAX on how often the system may be wrong and on edit/recover, and Google’s guidebook on telling people which data is shared ([AI Chat Interface Design: 10 UX Patterns](https://www.youtube.com/watch?v=HSZpvosKEYM); video date not retrieved). This video is a compilation, not a primary study. Primary versions of the same ideas: HAX G1 and the Copilot “can make mistakes” disclaimer ([Copilot in PowerPoint example](https://www.microsoft.com/en-us/haxtoolkit/example/copilot-in-powerpoint-1a-introductory-blurb/)); Salesforce’s required disclosure sentence ([AI agent design tips](https://www.salesforce.com/blog/ai-agent-design-tips/)); Carbon’s rule that the user must know AI is present ([Carbon for AI](https://www.carbondesignsystem.com/building-blocks/foundations/carbon-for-ai)); Fluent’s labeling and attribution ([Responsible AI](https://fluent2.microsoft.design/responsible-AI)); NN/g’s four transparencies — identity, capability, rationale, data ([5 Dimensions](https://www.nngroup.com/articles/dimensions-of-ai-chatbots/)).
- **Trust includes recovery and a record, which a button library does not carry.** Carbon’s revert-to-AI control is the small version ([Carbon for AI](https://www.carbondesignsystem.com/building-blocks/foundations/carbon-for-ai)). Yocco’s audit-and-undo pattern and his error copy (acknowledge, reverse, offer a human) are the large version (11 February 2026). Microsoft requires a visible status at all times and a way to view actions taken in the background, including actions with other agents (11 April 2025). OpenAI’s July 2025 post required permission, interrupt, takeover, and stop for consequential computer use, with the caveat that the post is now marked outdated ([Introducing ChatGPT agent](https://openai.com/index/introducing-chatgpt-agent/)).
- **Overreliance is called out as a design risk, not only a model risk.** The HAX Copilot examples say introductory blurbs and disclaimers can reduce overreliance and that mitigations can backfire, so they must be tested with the actual system ([Copilot in PowerPoint | 1A](https://www.microsoft.com/en-us/haxtoolkit/example/copilot-in-powerpoint-1a-introductory-blurb/); [Windows Copilot | G17](https://www.microsoft.com/en-us/haxtoolkit/example/windows-copilot-g17-provide-global-controls/)). Microsoft’s agent principles repeat that certainty and reasoning should be available “to avoid overreliance” (11 April 2025).
- **NN/g adds a behavioral difference from static components:** do not autoscroll a user who is reading, and do not use unlabeled icons for chat actions (guidelines 7 and the prompt-suggestions discussion, April 2026 and the prompt-suggestions article). Cloudscape agrees on autoscroll and adds that inline actions must be visible without hover, which is the opposite of a hover toolbar ([Generative AI chat](https://cloudscape.design/gen-ai/patterns/generative-ai-chat/); [10 Guidelines](https://www.nngroup.com/articles/ai-chatbots-design-guidelines/)).
- **Traditional libraries still apply underneath.** OpenAI’s UI guidelines restate WCAG AA contrast, alt text, and resize ([UI guidelines](https://developers.openai.com/plugins/concepts/ui-guidelines)). Carbon’s AI work sits on Carbon’s existing WCAG-oriented components; the AI-specific addition is the label and the explanation, not a new contrast rule ([Carbon for AI](https://www.carbondesignsystem.com/building-blocks/foundations/carbon-for-ai)).

### Inferences

- The practical difference from a traditional library is temporal and epistemic. Temporal: the UI updates when the user did not act, so live regions, focus, and scroll have new rules, and two reputable sources (Cloudscape in 2024, a11ypatterns in 2025) disagree on whether the new message itself is the live region. Epistemic: the component must show that the content might be wrong, what it was based on, and how to take it back. A button does not need those three.
- Trust work that is only a color, a sparkle, or a percentage fails the accessibility sources even when a design article recommends it.
- Memory and multi-agent trust are specified as principles (Microsoft: history, logs, on/off) and not yet as accessible components in the systems fetched.

### Gaps

- No W3C note written specifically for streaming generative responses was found. The WCAG hooks used by secondary guides are the existing 2.2 criteria, especially 4.1.3.
- Publication dates for accessibility.build, Slipstream, and River Group were not retrieved. Slipstream is a vendor describing its own components.
- Carbon’s accessibility section was cut off in the indexed page (“as the line between AI and human is becoming incre…”). The full accessibility checklist for Carbon for AI was not read.
- No source in this pass gives a tested pattern for announcing a multi-step tool trace to a screen reader without either silence or a flood.
